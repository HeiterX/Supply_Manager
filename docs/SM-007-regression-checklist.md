# SM-007 — финальная регрессия и протокол приёмки

Документ для ревью PR и комментария к [Issue #14](https://github.com/HeiterX/Supply_Manager/issues/14).

## Перед началом

- [ ] Запущена **отдельная тестовая среда** с тестовыми пользователями и без реальных корпоративных документов.
- [ ] В GitHub Actions успешно прошли `API`, `Web` и `Repository hygiene`.
- [ ] Подтверждён результат `npm audit` API и Web по логам задания (числа / серьёзность занести в Issue).
- [ ] SM-002/003/004/005/006 интегрированы, проверки PR выполнены повторно.

## Ручной smoke test закупочного цикла

- [ ] Анонимный пользователь создаёт заявку через `/request`.
- [ ] Проверить добавление нескольких позиций и **тестового** изображения.
- [ ] Авторизованный PROCUREMENT видит заявку в `/requests`, принимает её в работу.
- [ ] Создана закупка, исходные позиции и количества соответствуют заявке.
- [ ] Открываются `/`, `/registry`, `/tasks/[id]`, работают фильтры и загрузка данных.
- [ ] Позиция закупки добавляется и изменяется.
- [ ] Добавляется тестовое КП от поставщика и проверяется цена/валюта/срок.
- [ ] Позиции распределяются между двумя тестовыми поставщиками, оформляются отдельные заказы.
- [ ] Проходятся статусы заказа: создан, счёт получен, передан на оплату, оплачен.
- [ ] Отмечаются отгрузка, транзит, прибытие, получение и передача на склад/в производство.
- [ ] Закупка закрывается; итоговые данные и история сохраняются после обновления страницы.

## Безопасность и права

- [ ] Без cookie защищённые API отвечают `401`, интерфейс предлагает вход.
- [ ] Роль `EMPLOYEE` получает `403` при доступе к рабочим закупкам.
- [ ] `PROCUREMENT` и `ADMIN` могут читать и изменять разрешённые закупки.
- [ ] При удалении/истечении cookie защищённый экран скрывается после ответа `401`.
- [ ] Публичная заявка с фото без входа остаётся доступна после SM-004.
- [ ] Нельзя прочитать или заменить чужое фото только по UUID (после SM-004).
- [ ] При ошибках API интерфейс показывает понятное сообщение без раскрытия токенов/секретов.

## Воспроизводимость

- [ ] С чистого checkout: `npm ci` в `apps/api` и `apps/web`.
- [ ] Prisma Client генерируется командой `npx prisma generate` в `apps/api`.
- [ ] Применение миграций работает на изолированной схеме `e2e`.
- [ ] `npm run test:e2e` проходит; в логах зафиксировано фактическое число тестов (ожидается не менее 17 на базе SM-002).
- [ ] `npm run lint` и `npm run build` успешны в обоих приложениях.
- [ ] `git status --short` не содержит неожиданно отслеживаемых `.env`, дампов БД, загрузок или секретов.

## Протокол результатов (заполнять только по факту)

| Проверка | Факт / ссылка | Статус |
|---|---|---|
| CI API lint/build/E2E | Ссылка на Actions run | Не проверено |
| CI Web lint/build | Ссылка на Actions run | Не проверено |
| CI repository hygiene | Ссылка на Actions run | Не проверено |
| npm audit API | Уязвимости и ссылка на run | Не проверено |
| npm audit Web | Уязвимости и ссылка на run | Не проверено |
| Ручной сценарий закупки | Тестовые номера заявки / закупки (без секретов) | Не проверено |
| Проверка 401/403 и фото | Краткий результат | Не проверено |
| Ревью Тимофея | Ссылка на review | Не проверено |

**Ограничения:** этот чек-лист не является свидетельством проведённого тестирования, пока результаты не заполнены и не подтверждены ответственными. CI не заменяет ручной smoke test, аудит истории Git или контроль production-среды.

**Изменения вне SM-007:** IMAP, OCR, ML, перенос данных предприятия, production-интеграции.
