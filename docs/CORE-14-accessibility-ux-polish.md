## Контракт ошибок и повторения

- Клиент использует cookie и защищённые маршруты AuthGate. Ответ 401 очищает пользовательский экран и переводит фокус на вход. Формы и загруженные данные предыдущего сеанса удаляются вместе с защищённым деревом компонентов.
- Публичная заявка, регистрация, вход, создание закупки и позиции сопоставляют известные пути полей из массива ошибок NestJS с локальными подсказками. Неизвестный формат получает общее сообщение. Тело ошибки не вставляется в интерфейс.
- Ответ 429 сохраняет срок повторения, если передан `Retry-After` в секундах или HTTP-дате. Для cross-origin запросов NestJS публикует этот заголовок через CORS. У чтения есть ручной повтор с учётом задержки. В случае offline до отправки ввод сохраняется и повтор доступен после подключения.
- При таймауте, обрыве связи после начала отправки или ответе 5xx создание могло состояться. Повтор в том же черновике блокируется либо требуется сверка актуального состояния. Для принятия заявки и создания заказа используются серверные проверки статуса, повторного заказа и остатка. Общего ключа идемпотентности для публичной заявки, закупки и КП, а также атомарного `If-Match` для редактирования задачи в базе #44 нет.
- Механизм SM‑004 сохранён. Фото отправляется по выданному сервером токену. Повтор использует тот же маршрут и включает только оставшиеся файлы. Пароли, содержимое форм, фото и токены не записываются в localStorage.

## Производительность

Сравнены JavaScript-файлы из тегов `script src` статического HTML для локальных production-сборок CORE‑13 и CORE‑14. Размер рассчитан как сумма уникальных чанков после gzip. Это размер входных файлов, измерение рендеринга на устройстве сюда не входит.

| Маршрут | CORE‑13, КиБ | CORE‑14, КиБ |
| --- | ---: | ---: |
| Закупки | 183,7 | 186,6 |
| Реестр | 181,0 | 185,9 |
| Публичная заявка | 175,3 | 176,5 |
| Регистрация | 176,3 | 177,7 |

Реестр запрашивает нужную страницу на сервере при доступном CORE‑11. На синтетическом контракте проверена отрисовка страницы из 100 строк. При смене запроса предыдущая загрузка отменяется. Если маршрут CORE‑11 ответил 404, эта страница не запрашивает его повторно при каждом обновлении списка. Закрытие пустого диалога создания закупки больше не перечитывает список. В режиме совместимости сервер возвращает весь набор. React Profiler, замеры пользовательских метрик на физическом телефоне и большие выборки на сервере с объединённым CORE‑11 остаются отдельными проверками.

## Проверки

- Web и API: установка по lockfile, lint и production build, Web TypeScript. API: генерация Prisma, 2 unit-теста, 14 миграций в отдельной схеме `e2e` PostgreSQL 17 и 30 HTTP E2E. Web: 4 unit-теста.
- Локально прошли 15 проверок Playwright, включая вложенные сценарии и тест с реальным API. В CI те же проверки с синтетическим API используют Chromium. Browser plugin отсутствовал, локально использован установленный Chrome. Проверены 320, 375, 390, 768, 1024, 1440 и 1920 CSS px и длинные строки. В проверенных маршрутах ширина документа не превышала viewport.
- Для проверенных состояний прошли автоматические правила axe с тегами WCAG 2.0/2.1/2.2 A/AA. Проверены клавиатурный обход, видимый фокус, шаги форм, восстановление фокуса, доступные имена и контраст по правилам axe. Ручные NVDA, VoiceOver и QA с физической мобильной клавиатурой не выполнялись. [WCAG 2.2](https://www.w3.org/TR/WCAG22/)
- Реальный регрессионный проход: синтетическая заявка с PNG → вход снабженца по cookie → просмотр фото и принятие заявки → связанная закупка → два КП через UI → сравнение → частичный заказ. EMPLOYEE получил HTTP 403 на ту же закупку и экран ограничения доступа. ADMIN получил HTTP 200 и открыл карточку. Отдельный сценарий с изменением статуса ADMIN не выполнялся.

Локально запустите production build Web на `127.0.0.1:3391` с `NEXT_PUBLIC_API_URL=http://127.0.0.1:3390/api/v1`, затем `npm test` и `npm run test:browser` из `apps/web`. По умолчанию тесты используют синтетический API. Для реального сценария задайте `CORE13_REAL_API=1` и `CORE13_DATABASE_URL` для изолированного стенда CORE‑13 или CORE‑14, запустите API на 3390 с миграциями в схеме `e2e` и origin Web `http://127.0.0.1:3391`. Опциональные `CORE13_BROWSER_CHANNEL=chrome` и `CORE13_SCREENSHOTS` выбирают браузер и каталог снимков.
