- Расширен `.gitignore`: секретные env, runtime uploads, приватные документы,
  почта, backups, дампы/локальные базы, архивы, ключи, модели, кеши, сборка.
  SQL-миграции и синтетические тестовые ресурсы остаются разрешены.

  `apps/web/app/requests/page.tsx.backup-before-accept`; файлы на диске сохранены.
  Ни приложение, ни тесты не требуют этих файлов как исходных ресурсов.
- Пять проверенных снимков кода в `backups/` сохранены: массовая очистка архивов
  не выполнялась. Исправлен путь исключения нового generated Prisma;
  существующий отслеживаемый клиент не удалялся.
- Пароль Compose вынесен из исходников, локальный порт ограничен loopback.
  Добавлены безопасные шаблоны Compose/API/web и инструкция `SECURITY.md`.
- Удалена неиспользуемая шаблонная ссылка из API README.

Рабочая база, миграции, бизнес-логика и внешние пароли не изменялись.
Основная рабочая копия имела массовые staged deletions до начала аудита;
они не тронуты. Работа выполнена в отдельном worktree `.sm005-audit`.

## Остаточные риски и действия владельцев

1. **SEC-01 блокирует закрытие Issue #10.** Максим и Тимофей должны подтвердить
   порядок приватного разбора инцидента и согласовать удаление чувствительного
   объекта из истории всех затронутых веток/refs. До согласования history rewrite
   и force push не выполняются. После согласованной очистки нужно проверить
   PR refs/кеши с поддержкой GitHub и предупредить участников о старых клонах.
   Уже скопированные данные нельзя считать отозванными удалением из Git.
2. Проверить, использовался ли опубликованный пароль PostgreSQL в действующих
   средах. Если да — считать его скомпрометированным, сменить через ответственного
   администратора, обновить приватные настройки клиентов и проверить доступы.
   Обновлённый Compose не вращает пароль существующего volume автоматически.
3. Для JWT, Telegram, SMTP/IMAP и других внешних сервисов реальных ключей
   в доступных исходниках/истории не выявлено; их работоспособность не проверялась.
4. Этот PR удаляет файлы только из своей ветки. До merge они остаются в текущем
   `main`; merge также не очищает старые коммиты и другие ветки.
5. `.gitignore` не является DLP: `git add -f` и документы в иных каталогах могут
   обойти правила. Нужны ревью новых бинарных файлов и сканирование перед push.
