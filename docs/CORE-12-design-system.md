# CORE-12 — Дизайн-система Supply Manager

Связанные задачи: [CORE-12 #33](https://github.com/HeiterX/Supply_Manager/issues/33), [CORE-03 #24](https://github.com/HeiterX/Supply_Manager/issues/24) и [CORE-13 #34](https://github.com/HeiterX/Supply_Manager/issues/34).

## Визуальная система

Supply Manager использует светлый холст, белые рабочие поверхности и приглушённый синий акцент. Заголовок и контекстное действие расположены над содержимым. Состояния отличаются цветом и текстом. Критические сообщения используют красный, предупреждения — оранжевый, успех — зелёный.

| Назначение | Токен | Значение |
| --- | --- | --- |
| Холст и основные поверхности | `--background`, `--surface`, `--surface-subtle` | `#f5f7fb`, `#fff`, `#eef3f9` |
| Текст и вторичная информация | `--foreground`, `--muted` | `#182437`, `#4d5f76` |
| Границы панелей и контролов | `--border`, `--border-control` | `#dbe3ed`, `#8596aa` |
| Акцент | `--accent`, `--accent-hover`, `--accent-soft` | `#2858a5`, `#204782`, `#e5efff` |
| Успех, предупреждение, ошибка | `--success`, `--warning`, `--danger` | `#176043`, `#84510e`, `#a52b38` |
| Геометрия | `--space`, `--radius`, `--radius-panel`, `--control` | 4, 10, 14 и 44 CSS px при стандартном размере шрифта |
| Слои и движение | `--z-sticky`, `--z-toast`, `--duration` | 20, 40, 150 мс. Диалоги и меню пользователя используют нативный верхний слой браузера |

Токены определены в `apps/web/app/globals.css`. Tailwind 4 получает семантические цвета холста, поверхности, текста и акцента через `@theme inline`. Панели используют `--shadow-panel`, всплывающие поверхности — `--shadow-overlay`. Интерфейс использует локальный Geist с Arial в качестве запасного шрифта. Заголовки страниц масштабируются от 24 до 32 px. Основные контролы используют 14 px, подписи и статусы — 12 px. Анимации и переходы сокращаются при `prefers-reduced-motion`.

## Компоненты для рабочих экранов

| Компонент | Использование |
| --- | --- |
| `PageLayout` | Заголовок, описание и контекстное действие. |
| `Button` | `primary`, `secondary`, `outline`, `ghost`, `destructive`, а также `loading`, `disabled` и `icon`. У кнопки с одной иконкой задайте `aria-label`. Ссылки используют Next Link и классы `ui-button`. |
| `Input`, `Textarea`, `Select`, `Field` | Нативные элементы ввода с едиными состояниями. Для ошибки укажите `aria-invalid` и `aria-describedby` со ссылкой на сообщение поля. Для checkbox и radio используйте `ui-choice`, для переключателя — checkbox с `role="switch"` и `ui-switch`. |
| `Card`, `Badge`, `StatusBadge`, `Avatar` | Панели, семантические статусы закупок и заявок, инициалы пользователя. Разделитель — `hr.ui-divider`. Свёрнутые пункты отображают подписи через нативный `title`, доступное имя задано явно. |
| `TableRegion` | Подписанный фокусируемый контейнер с локальной горизонтальной прокруткой. Внутри используйте семантическую таблицу с заголовками столбцов и строк. |
| `ui-tabs` | Горизонтальная группа кнопок переключения вида. Активная кнопка отмечается `aria-pressed`. |
| `Alert`, `LoadError`, `Toast`, `EmptyState`, `Skeleton`, `Spinner` | Сообщения, повтор запроса, подтверждение операции, пустые списки и состояния загрузки. Toast имеет явную кнопку закрытия. |
| `Dialog`, `Modal`, `ModalActions`, `useConfirmation` | Нативный модальный диалог с фокусом внутри, Escape и возвратом фокуса. Для первоначального фокуса укажите `data-initial-focus`. Пока запрос выполняется, передайте `busy` в диалог и его действия. |
| `AppShell` | Боковая панель, хлебные крошки, поиск по разделам, меню пользователя и мобильная навигация. |

```tsx
import { Button, Field, Input, TableRegion } from '@/app/components/ui';

<Field id="item-name" label="Позиция" error={error}>
  <Input id="item-name" name="name" required
    aria-invalid={Boolean(error)}
    aria-describedby={error ? 'item-name-error' : undefined} />
</Field>

<Button type="submit" loading={saving}>Сохранить</Button>

<TableRegion label="Позиции закупки">
  <table>
    <thead><tr><th scope="col">Позиция</th></tr></thead>
    <tbody><tr><td>Прокладка</td></tr></tbody>
  </table>
</TableRegion>
```

## Оболочка и доступ

`app/(workspace)/layout.tsx` держит один `AuthGate` и `AppShell` для всех рабочих маршрутов. Next Link сохраняет оболочку при переходах. Свёрнутое состояние боковой панели запоминается в браузере. `navigation.ts` описывает маршруты и разрешённые роли. Вложенный `/tasks/[id]` подсвечивает «Закупки» и показывает путь «Главная → Закупки → Карточка закупки». Старые ссылки на список и карточку сохраняют адреса.

| Маршрут | ADMIN | PROCUREMENT | EMPLOYEE |
| --- | --- | --- | --- |
| `/dashboard` | Обзор закупок | Обзор закупок | Быстрые действия сотрудника |
| `/`, `/registry`, `/requests`, `/tasks/[id]` | Доступ | Доступ | Экран 403 |
| `/my-requests` | — | — | Свои заявки через `GET /purchase-requests/mine` |
| `/request` | Публичная форма | Публичная форма | Публичная форма |

Меню основано на текущих NestJS guards. Сервер проверяет cookie-JWT, роль и владение объектами. При ответе 401 на защищённый запрос оболочка скрывает содержимое и показывает вход. Ответ 403 показывает отказ внутри рабочего пространства. Выход вызывает `POST /auth/logout`. Поиск в шапке находит доступные разделы. Штатный слот `AppShell.tools` предназначен для подключения элементов верхней панели.

До 768 px навигация открывается в выдвижном диалоге. Начиная с 768 px доступна сворачиваемая панель. Начиная с 1024 px верхняя панель показывает подпись поиска и имя с ролью. Ключевые списки используют мобильные карточки и прокручиваемые таблицы. Модальные окна ограничены высотой экрана. Ссылка «К содержимому» доступна при клавиатурном фокусе.

## Макеты и локальное воспроизведение

[Концепт пяти экранов и мобильной главной](CORE-12-concept.png) использует вымышленные примеры. В приложении главная отображает данные действующего API. Текущий объём реализации приведён в таблице.

| Экран | Где открыть | Что проверить при просмотре |
| --- | --- | --- |
| Главная | `/dashboard` | Приветствие, показатели, недавние и просроченные закупки, быстрые ссылки. На телефоне блоки идут вертикально. |
| Список закупок | `/` | Поиск, фильтры, этап, приоритет, следующее действие, срок, создание и уведомление об успехе. Требования макета к ответственному и пагинации переходят в CORE-13. |
| Карточка закупки | `/tasks/<id>` | Обзор текущего действия, позиции, предложения, заказы и история. Оплаты и доставка доступны в разделе заказов. |
| Публичная форма | `/request` без входа | Имя, позиции, количество, единица, техническое описание, фото, ошибки и подтверждение. Поле срока потребности зависит от расширения публичного контракта. |
| Сравнение КП | Карточка → «Предложения» | Поставщик, позиции, цены за единицу, валюта, срок, наличие, условия и переход к действиям предложения. Длинные значения переносятся, отсутствующие отмечены прочерком, таблица прокручивается в своей области. |

Запустите API и web по их README с отдельной локальной БД. Под тестовой учётной записью снабженца создайте закупку с прошедшим сроком, добавьте позицию и два коммерческих предложения с разными ценами и сроками. Откройте главную, список и карточку. Для мобильной проверки повторите проход при ширине 375 px. Публичная форма доступна в отдельном окне без авторизации. Для проверки «Моих заявок» создайте синтетическую заявку через авторизованный `POST /purchase-requests`. Публичная заявка сохраняет имя заявителя и не связывается автоматически с учётной записью.

## Зависимости и ревью

- [CORE-02 PR #39](https://github.com/HeiterX/Supply_Manager/pull/39) улучшает переносимость E2E и расширяет CI. CORE‑12 отслеживает текущую базу `main`.
- [CORE-03 #24](https://github.com/HeiterX/Supply_Manager/issues/24) определяет будущие административные маршруты и управление ролями. Поставщики, номенклатура, документы, отчёты, администрирование и настройки появятся в меню после появления рабочих маршрутов.
- [CORE-09 PR #40](https://github.com/HeiterX/Supply_Manager/pull/40) содержит клиентский провайдер и центр уведомлений. После объединения подключите провайдер внутри `AuthGate`, а кнопку центра передайте через `AppShell.tools`. События сессии остаются в существующем API-клиенте. Серверные правила Next Action остаются в CORE‑09.
- [CORE-10 PR #41](https://github.com/HeiterX/Supply_Manager/pull/41) и [CORE-11 #32](https://github.com/HeiterX/Supply_Manager/issues/32) определяют будущие настройки Telegram и поиск по данным. Поиск разделов можно расширить при интеграции CORE‑11.
- Для [CORE-13 #34](https://github.com/HeiterX/Supply_Manager/issues/34) готовы токены, общий заголовок, поля, таблицы, статусы, диалоги, подтверждения и обратная связь. Максиму на ревью стоит пройти создание закупки, сравнение КП, отправку заявки с фото и роли на мобильном экране. Согласование макетов и комплексная WCAG-проверка остаются отдельными этапами.
