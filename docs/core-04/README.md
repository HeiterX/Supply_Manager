# CORE-04 — Полный цикл заявки сотрудника

Связанная задача: GitHub Issue #25.

## Назначение

Модуль позволяет сотруднику подать заявку на закупку
запчастей и комплектующих, а отделу снабжения —
рассмотреть её и при необходимости создать закупку.

## Подача заявки

Публичная форма `/request` поддерживает:

- ФИО заявителя;
- несколько позиций потребности;
- наименование, количество, единицу измерения;
- описание и фотографию позиции;
- приоритет и необходимый срок;
- валидацию введённых данных;
- подтверждение успешной отправки.

Фотографии загружаются отдельно с использованием
краткосрочного токена загрузки.

## Черновики

Незаполненную заявку можно сохранить локально
в браузере и восстановить позднее.

Черновики:
- сохраняются только по действию пользователя;
- не создают запись в базе данных;
- не содержат файлов фотографий;
- удаляются после успешной отправки заявки.

Не использовать черновики для конфиденциальных данных
на общедоступных компьютерах.

## Обработка заявки

PROCUREMENT и ADMIN могут:

- просматривать входящие заявки;
- брать новые заявки на рассмотрение;
- отклонять заявки с обязательной причиной;
- принимать заявки и создавать закупку;
- просматривать историю действий и ответственного.

Используются существующие статусы Prisma:

- NEW — новая заявка;
- IN_REVIEW — на рассмотрении;
- REJECTED — отклонена;
- CONVERTED — преобразована в закупку.

В Prisma также существуют дополнительные статусы,
однако отдельные переходы для них не реализуются
в рамках CORE-04.

## Преобразование в закупку

Принятие заявки выполняется в транзакции PostgreSQL
с блокировкой исходной записи.

Создаётся одна закупка Task с исходными позициями.
Повторное принятие не должно создавать второй Task.

В PurchaseRequest сохраняется ссылка taskId.

Фотографии остаются у PurchaseRequestItem.
Карточка Task показывает фотографии через связь
sourceRequest, без копирования исходных файлов.

## Разграничение доступа

- EMPLOYEE видит только собственные авторизованные заявки.
- PROCUREMENT и ADMIN работают со входящими заявками.
- Публичная форма доступна без регистрации.
- Просмотр фотографий защищён проверками доступа.
- Изменяющие запросы используют существующую
  инфраструктуру авторизации и CSRF-защиты.

## Основные маршруты API

POST  /api/v1/purchase-requests/public
POST  /api/v1/purchase-requests
GET   /api/v1/purchase-requests/mine
GET   /api/v1/purchase-requests
GET   /api/v1/purchase-requests/:id
PATCH /api/v1/purchase-requests/:id/review
PATCH /api/v1/purchase-requests/:id/reject
PATCH /api/v1/purchase-requests/:id/accept

## Проверка

API:
npm run lint
npm run build
npm run test:e2e

Web:
npm run lint
npm run build

E2E запускаются через test/run-e2e.sh,
который проверяет изоляцию тестовой схемы e2e.

Дополнительно выполнена ручная проверка публичной
формы, обработки заявок, черновиков и фотографий.

## Ограничения

- Черновики доступны только в исходном браузере.
- Фотографии в локальных черновиках не сохраняются.
- Перенос вложений непосредственно в TaskItem
  не выполняется: сохраняется ссылка на исходную заявку.
