# Безопасная локальная конфигурация

1. Скопируйте корневой `.env.example` в `.env`. Сгенерируйте случайный
   `POSTGRES_PASSWORD` (например, `openssl rand -hex 32`), сохраните его только локально.
2. Скопируйте `apps/api/.env.example` в `apps/api/.env`. Укажите тот же пароль
   в `DATABASE_URL`, закодировав специальные символы для URL. Сгенерируйте отдельный
   случайный `JWT_SECRET` минимум из 32 символов. Пустой секрет намеренно не работает.
3. Скопируйте `apps/web/.env.example` в `apps/web/.env.local`. Все переменные
   `NEXT_PUBLIC_*` доступны пользователям браузера и не должны содержать секреты.
4. Telegram включается только с собственными приватными настройками. SMTP/IMAP
   пока не реализованы; закомментированные имена в шаблоне не включают интеграцию.

Compose предназначен для локальной разработки: PostgreSQL доступен через
`127.0.0.1:5432`. Команды `docker compose config --quiet` достаточно для проверки
конфигурации; полный `docker compose config` может напечатать пароль.
Изменение `.env` **не меняет пароль в существующем volume PostgreSQL**.
Не удаляйте volume ради смены пароля: ротацию согласуйте с владельцем базы.

Для E2E создайте приватный `apps/api/.env.test` с отдельным `DATABASE_URL`,
обязательно содержащим `schema=e2e`. Предпочтительна отдельная тестовая база
или контейнер. Штатный `npm run test:e2e` проверяет изоляцию до миграций.
Никогда не используйте рабочую схему для E2E.

Пользовательские файлы сохраняются в `apps/api/uploads/` только локально.
`backups/`, `private-documents/`, `commercial-documents/`, `attachments/` и
`mailbox/` предназначены для приватных материалов и исключены из новых добавлений.
Проверенные старые исходники в `backups/` остаются отслеживаемыми: `.gitignore`
не удаляет существующие файлы из индекса. Новые тестовые изображения должны быть
синтетическими и находиться в `test/fixtures/`; реальные документы не используйте.
Не добавляйте все фотографии или офисные документы в произвольные каталоги:
расширения исходных ресурсов сами по себе не определяют конфиденциальность.

Перед публикацией проверяйте `git diff --cached --stat`, `git ls-files` и
`git check-ignore --no-index <путь>`. Выполняйте Gitleaks локально:

```sh
gitleaks git . --log-opts=--all --redact=100
gitleaks git . --staged --redact=100
```

Сканер секретов не распознаёт персональные данные на фотографиях. Проверяйте
добавляемые бинарные файлы вручную. Не публикуйте исходные отчёты сканеров,
секреты, фрагменты реальных документов или скриншоты с ними.

При утечке прекратите дальнейшее распространение, сообщите владельцам приватно,
отзовите/замените затронутые учётные данные через ответственного администратора.
Удаление из текущей ветки не удаляет историю, PR refs, клоны или кеши GitHub.
Очистка истории требует отдельного согласования и координации всех участников;
не выполняйте force push самостоятельно. Результаты SM-005 — в
`docs/security/sm-005-audit.md`.
